# Stage 7 — Полная интеграция (по спросу)

Фаза 4 плана [risks/04 §4.5](../../smj-research/risks/04-implementation-plan-with-risk-gates.md).

## Цель

Избирательное расширение покрытия SMJ за пределы MVP+CBO: FTE, семи-джоины, диапазонное
партиционирование и курсорные оптимизации — каждый пункт только при подтверждённом спросе.

## Состав работ (меню мини-планов)

Каждый пункт — отдельный мини-план с теми же гейтами; выполняется selectively по спросу.

## Пункты (порядок — по соотношению ценность/усилия)

| # | Пункт | Суть | Риск/док |
|---|---|---|---|
| 7.1 | FTE ordered spooling | merge-источники при `retryPolicy != NONE`: упорядоченный спулинг партиций exchange-manager'ом; открывает SMJ под fault-tolerant execution | I1-полное; 04 §4.5 |
| 7.2 | ReorderJoins SMJ-aware | JoinGraph-перестановки учитывают merge-стоимость (через cost stage 6) | 04 §4.5; 03 §3.10 (ReorderJoins опц.) |
| 7.3 | SemiJoin | sorted-merge semi-join (probe-только вывод, группа не буферизуется — проще FULL) | 04 §4.5 |
| 7.4 | Range-partitioning по Iceberg min/max | разбиение диапазонами вместо hash — co-location для sorted-не-bucketed | P7-полное; 04 §4.5 |
| 7.5 | MergePath-параллелизм merge | декомпозиция слияния на независимые интервалы внутри драйвера (однопоточный merge — bottleneck на single-hot-partition) | P9; risks/03 §3.9 |
| 7.6 | Order-preserving casts | вывод sortedness через кастующие projections (смягчение missed-opportunities) | C6-смягчение |
| 7.7 | Cursor-driven range-split-skip | low-watermark ключа + отмена сплитов с `max(k) < watermark`; **только S1-GOLD** (после REPARTITION порядок hash(k)); обязательно против DF-бейзлайна | P12; risks/08 §8.3 |

## Общие гейты для каждого пункта

- OFF-режим: 0 диффов планов; oracle против hash; откат за флагом;
- acceptance-критерии формулируются в мини-плане пункта до старта (та же форма, что у этапов 0-6).

## Откат

Каждый пункт независим и за собственным флагом; отключение пункта не влияет на этапы 0-6.
