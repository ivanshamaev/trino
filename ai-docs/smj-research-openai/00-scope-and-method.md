# Методика и границы

Работа опирается на исходники текущего checkout, документацию в `docs/src/main/sphinx`, официальные материалы других движков и их исходники с фиксированными tags. Старые исследования в `ai-docs` не использовались. Поиск по Trino ограничивался `core`, `testing`, `plugin`, `lib`, `docs` и служебными файлами репозитория; для новых результатов использован только этот каталог.

Базовая версия — `485-SNAPSHOT`, commit `e112ffdf7304333b50bfdff50dda4229c897896d`, версия из [pom.xml](../../pom.xml). Привязка к commit важнее маркетинговой версии: checkout содержит конкретный набор возможностей. Ссылки на Java-файлы ведут к локальному checkout; имена методов указаны рядом, поскольку номера строк меняются.

Три уровня утверждений:

- **Факт кода** — наблюдается в указанном классе или методе текущего checkout.
- **Вывод** — следствие фактов и алгоритмического анализа; ещё не измеренная характеристика реализации.
- **Предложение** — контракт, изменение planner/operator или эксперимент для будущей разработки.

Отсутствие general-purpose SMJ установлено по ветвлению `LocalExecutionPlanner.visitJoin`, доступным join factories и поиску merge-join реализаций в основном коде и тестах. Это не утверждение об отсутствии JOIN pushdown в удалённые БД или экспериментальных сторонних fork.

Пять отдельных агентов исследовали проблему с ролями Java developer, Java architect, Java optimization engineer, MPP engine architect и Trino developer. Из-за ограничения числа одновременно работающих агентов использованы две волны. Это пять участников, а не пять названий одной записки. Детали обсуждения и cross-review собраны в [09](09-five-agent-brainstorm.md).

Внешние исходники для анализа: Spark `v4.0.1`, ClickHouse `v25.3.3.42-lts`; это выбранные воспроизводимые версии, **не утверждение, что они последние**. Документация Vertica взята для 24.2.x. Современные возможности не экстраполируются назад на tags. Статьи служат источниками идей, их performance claims не переносятся на Trino.

Не выполнялись сборка Trino, SQL-запуски, JVM profiling и кластерные benchmarks. Для изменения только Markdown сборка не даёт полезного подтверждения алгоритма. Проверены ссылки на локальные файлы и согласованность итоговых документов. Псевдокод и формулы являются проектными материалами; доказательство корректности будущей реализации потребует тестов из [08](08-validation-and-benchmarks.md).

Главное ограничение исследования: без профиля реальной нагрузки нельзя выбрать универсальный порог переключения hash → merge или обещать ускорение. Нужны размеры после фильтрации и projection, частоты ключей, RAM на task, локальный диск, сеть, concurrency и целевая latency. Исследование задаёт способ получить эти ответы.

Проверка первого этапа: 18 Markdown-файлов, 241 локальная ссылка на существующие файлы, отсутствующие цели ссылок не обнаружены. Проверены парность code fences, trailing whitespace и завершающий перевод строки. Два участника дополнительно проверили общие алгоритмические и архитектурные главы; замечания о candidate groups, tile I/O estimate и повторном physical planning внесены в итог. Эти проверки подтверждают качество документации, а не работоспособность ещё не написанного SMJ.

Дополнительный этап исследует полностью unsorted JOIN 15 млрд × 17 млрд, несовпадение storage partition/bucket keys с join keys и Java sorting paths в ядре/Hive/Iceberg. Добавлены главы 12–15, JSON допущений и CSV 16 расчётных сценариев. Velox не рассматривается. Новая находка — bounded multipass в connector SortingFileWriter — внесена в общие рекомендации; это уточнение области reuse, а не изменение фактов о текущем OrderByOperator. Арифметика resource model проверена программно; Java benchmarks и реализация SMJ по-прежнему не выполнялись.

Проверка после дополнения: 22 Markdown-файла и 310 локальных ссылок без отсутствующих целей; JSON прочитан, все 16 строк CSV пересчитаны независимой арифметической процедурой. Дополнительно проверены контрпример несовместимых composite buckets и схлопывание parallelism при учебном повторном modulo по тем же hash bits. Это проверки модели/документации, не engine-level tests.
